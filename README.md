# Розклад уроків · Ліцей №11

Розклад уроків Ліцею №11 Івано-Франківської міської ради — **4–11 класи**.

Маленький статичний сайт, який ставиться на телефон як застосунок і працює без
інтернету. Показує, який урок іде зараз, скільки до дзвінка, що буде далі, і
вміє показувати розклад окремо «мій» і «повний, з усіма групами».

Ніяких оцінок, домашніх завдань, акаунтів і сервера — тільки розклад.

## Що вміє

- **Що зараз.** Поточний урок із зворотним відліком і смужкою прогресу, перерва,
  «перший урок через N хв», «уроки закінчилися».
- **Свій клас.** 24 класи з 4-го по 11-й, обидві зміни. Клас обирається один раз.
- **Свої групи.** Навчальна група, друга іноземна, підгрупа англійської, поділ на
  фізкультурі. Питаємо лише про ті поділи, які в цьому класі справді є.
  Уроку, якого у вашої групи немає, ви не бачите.
- **Вчителі.** Підписані так, як до них звертаються: «Галина Богданівна Ж.».
  Прізвище скорочене рівно настільки, щоб не сплутати тезок.
- **Кабінети.** Показуються там, де вони є в офіційному розкладі. Номери — як
  «каб. 12», зали — як у розкладі («сз», «тз»). На фізкультурі зал залежить від
  поділу.
- **Чергування по тижнях.** Уроки «через тиждень» рахуються від того тижня, у
  якому починається навчальний рік: він перший.
- **Вихідні.** У суботу й неділю показує найближчий навчальний день.
- **Завдання.** Домашка й нагадування, записані до уроків, збираються в
  один список: що попереду, згруповане по днях, з переходом на потрібний
  день. У стрічці дат такі дні позначені крапкою.
- **Нотатка на день.** Окреме поле над розкладом — для того, що не належить
  жодному уроку: чергування, прибирання, що взяти з собою. Потрапляє в той
  самий список завдань, першим записом свого дня.
- **Меню їдальні.** Чіп «Меню» над розкладом: сніданок і обід ГПД на кожен
  день тижня з виходом кожної страви. Відкривається на тому дні, який зараз
  переглядаєте.
- **Тиждень одним екраном.** Кнопка «Весь тиждень» над розкладом: усі п'ять днів
  разом, з вікнами й підсвіченим сьогоднішнім днем. Працює і для класу, і для
  вчителя, обидва тижні чергування.
- **Розклад учителя.** Вчитель вмикає себе в налаштуваннях і бачить свій день по
  всіх класах одразу — з класом на кожній картці й **вікнами** (пропущеними
  уроками) між ними. Працює так само, як в учня: що зараз, скільки до дзвінка,
  нотатки.
- **Довідник учителів.** Іконка людини в шапці: хто стоїть за яким кодом
  розкладу, що і в яких класах веде, де класний керівник, і тижневий розклад
  кожного з вікнами. У картці видно, **де вчитель просто зараз** — який клас,
  який кабінет і до котрої, — щоб не шукати його поверхами.
- **Теми.** Світла, темна, або як у системі.
- **Підручники.** Каталог PDF-підручників класу — відкрити з іконки книжок
  у шапці й завантажити в один дотик. Учитель бачить свій предмет у кожній
  паралелі, де він викладає, а не перелік одного класу.
- **Як застосунок, не як сайт.** Смужки скролу на дотику немає, аркуші
  змахуються вниз, інтерфейс не виділяється й не зумиться від подвійного тапу.
- **Офлайн.** Після першого відкриття працює без мережі.
- **Само оновлюється.** Нову версію застосунок підхоплює сам — перевстановлювати
  його не треба.

Час завжди рахується за **Europe/Kyiv**, незалежно від годинника пристрою.

## Запуск локально

```bash
npm install
npm run dev
```

Сайт відкриється на `http://localhost:5173/school-schedule/` — підпапка в адресі
навмисна, бо саме так він живе на GitHub Pages.

## Збірка

```bash
npm run build      # перевірка типів + збірка у dist/
npm run preview    # подивитись зібрану версію (тут працює service worker)
npm run lint
npm test           # логіка часу, груп, кабінетів і перенесення налаштувань
```

Service worker вмикається лише у зібраній версії, тому офлайн перевіряйте через
`npm run preview`, а не `npm run dev`.

## Деплой

Кожен push у `main` запускає `.github/workflows/deploy.yml`: перевірка типів →
лінт → тести → збірка → публікація на GitHub Pages.

У налаштуваннях репозиторію **Settings → Pages → Source** має стояти
**GitHub Actions**. Базовий шлях заданий у [`vite.config.ts`](vite.config.ts) як
`/school-schedule/` — він має збігатися з назвою репозиторію.

## Де редагувати розклад

Дані розділені на дві частини:

**[`src/data/schedule.ts`](src/data/schedule.ts)** — довідники, правляться руками:

- `BELLS` — розклад дзвінків, 12 періодів. Час живе тільки тут.
- `SUBJECTS` — скорочення з паперового розкладу → повна назва.
- `TEACHERS` — розшифровка кодів учителів.
- `GROUP_LABEL`, `GROUP_DIM` — як називаються групи і за якою ознакою ділять клас.

**[`src/data/teachers.ts`](src/data/teachers.ts)** — хто стоїть за кодами
вчителів; згенеровано, правиться через `scripts/import-teachers.mjs`.

**[`src/data/timetable.ts`](src/data/timetable.ts)** — самі уроки, згенеровані з
офіційного PDF. Правити руками можна, але при повторному імпорті правки треба
перенести в скрипт.

Один урок виглядає так:

```ts
{ p: 4, c: [{ s: 'ум', r: '16', t: 'ГЖ', g: '1' }, { s: 'к', t: 'ГД', g: '2' }] },
```

- `p` — номер періоду за `BELLS` (наскрізний, 1–12: 1–6 перша зміна, 7–12 друга).
- `s` — предмет, `r` — кабінет, `t` — код учителя.
- `g` — кому цей варіант: `'1'`/`'2'` навчальна група, `'а'`/`'б'`/`'в'`
  англійська, `'н'`/`'ф'` друга іноземна, `'х'`/`'д'` поділ на фізкультурі,
  `'т1'`/`'т2'` чергування по тижнях.
- `w` — урок буває лише на тижнях цієї парності.

Немає кабінета в паперовому розкладі — просто не пишіть `r`: в інтерфейсі нічого
не з'явиться, і жодних «не вказано» користувач не побачить. Так само з `t`.

### Оновити розклад із нового PDF

```bash
npm i -D pdfjs-dist
node scripts/import-timetable.mjs "Розклад класи.pdf"
```

Скрипт розбирає вивантаження з aSc Розклад (предмет по центру комірки, кабінет
знизу ліворуч, вчитель знизу праворуч) і перезаписує `timetable.ts`.

Уточнення, яких у PDF не видно, живуть у самому скрипті й переживають
повторний імпорт:

- `OVERRIDES` — правки однієї комірки, за ключем «клас Дн+період»;
- `CLASS_FIXES` — правки на весь клас: інший порядок уроків, доданий урок,
  перенесення між днями.

Далі накладаються два зовнішні джерела, у такому порядку:
[`vchyteli.mjs`](scripts/vchyteli.mjs) — учительський вивантаж aSc, і
[`kabinety.mjs`](scripts/kabinety.mjs) — паперовий розклад зі школи, за яким
лишається останнє слово.

### Що додає учительський розклад

Той самий вивантаж aSc, але сторінка на вчителя, а не на клас
(«Розклад вчителі-26.pdf»). Предметну сітку він не міняє — 803 із 816 слотів
збіглися дослівно, а решта 13 це рівно ті, що вже виправлені за папером. Зате
в ньому видно те, чого класний вигляд не друкує:

- **домашній кабінет класу.** У класному вигляді aSc його ховає, в
  учительському — друкує. Так у 4–6 паралелях знайшлися кабінети на
  понеділок і вівторок, яких паперовий розклад не покриває; фізкультуру
  пропущено навмисно, бо їй aSc ставить той самий домашній кабінет, хоч
  насправді це зал.
- **хто веде урок.** Кожна сторінка підписана повним іменем, тож спільні
  дволітерні коди розводяться однозначно — див. нижче про `ОК`, `ГП` і `ОГ`.
- **чергування по тижнях**, якого в класному вигляді не розпізнати: географія
  проти другої іноземної в 9-А (середа) і 9-Б (п'ятниця).

Усі такі правки лежать у [`scripts/vchyteli.mjs`](scripts/vchyteli.mjs) за тим
самим ключем «клас Дн+період»; значення — по об'єкту на комірку уроку, у тому ж
порядку, що й у розкладі. Накладаються перед `kabinety.mjs`.

### Карта кабінетів (бета)

Іконка дверей у шапці відкриває [`RoomsSheet`](src/components/RoomsSheet.tsx): хто де сидить
на вибраному уроці й що лишається вільним. День і урок перемикаються вгорі, на відкритті
підставляється поточний.

Рахунок живе в [`src/lib/rooms.ts`](src/lib/rooms.ts) і робить рівно одне: проходить
`TIMETABLE` і збирає комірки з `r` на потрібний день, урок і парність тижня. Тому
**«вільний» тут означає лише «за розкладом ніхто не записаний»** — ні замін, ні перенесень,
ні позаурочних заходів ми не бачимо. Плюс два перекоси, про які написано просто в шторці:

- кабінети стоять лише в середу, четвер і п'ятницю (див. `kabinety.mjs`) — у понеділок і
  вівторок їх помітно менше, тож «вільних» там більше, ніж насправді;
- 1–3 класів у розкладі немає взагалі, і їхні кабінети (21, 22, 24, 26, 27, 29) завжди
  здаються вільними.

### Уроки «через тиждень»

Урок, який буває раз на два тижні, aSc малює **половиною комірки без підпису
групи**. На паперовому розкладі його підписують «історія//» або «//хімія»:
риски позаду — перший тиждень, спереду — другий.

Розбір розпізнає це сам (`halfOnly`) і ставить комірці `w`. Таких уроків
десять, майже всі — остання історія чи хімія в дні 8–11 класів. Поки правило
було ручним винятком на один клас, решта дев'ять показувались щотижня.

Ще двадцять комірок додає учительський розклад:

- у 9-А (середа, 2 урок) і 9-Б (п'ятниця, 3 урок) географія чергується з
  другою іноземною — у класному вигляді там три предмети в одній годині, і
  правило `halfOnly` не спрацьовує;
- на інформатику в 8-х і 9-х групи ходять **по черзі**, а не разом: перша на
  першому тижні, друга на другому. В учительському розкладі це дві півкартки в
  одній годині — учитель не може вести обидві одразу, — а на папері зі стенду
  так і підписано: «інф I//інф II». У 9-В групи ще й міняються місцями з
  німецькою.

### Кабінети з паперового розкладу

Школа видала паперовий розклад із кабінетами вже після PDF. Кабінети на ньому
стоять у **середу, четвер і п'ятницю** — у понеділок і вівторок жодного, — і
там, де він дає інший номер, правда за ним.

Усі 403 уроки лежать у [`scripts/kabinety.mjs`](scripts/kabinety.mjs) за тим
самим ключем «клас Дн+період», і в коментарі кожного рядка — рядок паперового
розкладу, з якого він узятий. Імпорт накладає їх останнім кроком.

Крім номерів на папері трапляються назви: `сз` — спортзал, `акт.зал` — актова
зала (туди ходить «Навчаємось разом» у 6-А і 5-Г), `бібл` — бібліотека (там
сидить третя підгрупа англійської в 10-х і 11-х). `roomLabel` показує їх як є,
без «каб.».

Порожній рядок у значенні означає «лишити те, що в PDF» — так стоїть там, де
папір номера не дає або де його не вдалося прочитати.

Предметну сітку той папір майже не змінює: із 709 звірених уроків розходились
п'ять, і всі перенесені в `CLASS_FIXES`:

- **6-А** — понеділок в іншому порядку, і математики в PDF на сім уроків лише
  шість; у п'ятницю навпаки: нульового уроку немає (це видно на фото стенду), а
  PDF ставить математику двічі підряд;
- **7-А** — образотворче з музикою і математика місцями між вівторком і середою
  (середу підтверджує фото стенду).

Дві правки знято після ближчих фото:

- **5-Б**, останній урок четверга: на стенді від руки написано «укр. літ», як і
  в PDF, а не «укр/англ»;
- **5-Д**, понеділок: перестановка 2-го й 3-го уроків садила Любов Білічак
  одночасно в 5-В і 5-Д, ще й в один кабінет. Без неї конфлікту немає.

Понеділок 6-А теж довелося зсунути на урок раніше: математика стоїть
**«мінус першим»** уроком, об 11:55, а не нульовим. Поки весь день стояв на
урок пізніше, шість уроків 6-А накладались на інші класи — та сама Наталія
Овчар мала б водночас вести математику в 5-В.

### Оновити список учителів

```bash
node scripts/import-teachers.mjs учителя.json
```

Вхід — вивантаження `GET /v1/{school}/Teacher` зі шкільного журналу. Скрипт
залишає тих, хто справді веде уроки в 4–11 класах, і зшиває їх із кодами
розкладу. Звільнених не переносить.

Коди в розкладі — це перша літера імені плюс перша літера прізвища: «ХБ» —
Христина Братина. Трилітерний код розводить тезок: «СВС» — Савчук Світлана
**В**асилівна, бо Савчук Світлан у школі дві. Один код зібрано навпаки, з
прізвища та імені, — «ВЮ», Варварук Юлія. Таблиця `CODES` усередині скрипта —
єдине місце, де ця розшифровка живе.

Шість кодів у розкладі спільні для двох різних учителів (aSc дозволив збіг),
а `ОК` і `ГП` — навіть для трьох. Їх розводимо за предметом, а де предмета
мало — ще й за класом:

```js
ЛЧ: [
  { who: 'Чорній Леся Юліянівна',   when: [{ s: ['мм', 'хе'] }, { s: ['нр', 'т'], in: ['7в'] }] },
  { who: 'Човган Лариса Михайлівна', when: [{ s: ['іст'] },      { s: ['нр', 'т'], in: ['9а'] }] },
]
```

Хто під яким кодом ходить, показав учительський розклад: там кожна сторінка
підписана повним іменем. Він же виправив три місця, де ми помилялись:

- **`ОК`** — Ольг К. троє. Українську веде **Курман**, а не Козак; англійську
  ведуть **Козак** (4-Б, 4-В, 6-А, 6-Б) і **Кравчишин** (5-Д, 7-А, 7-Б) —
  предмет їх не розводить, тільки клас.
- **`ГП`** — 34 уроки математики й інформатики стояли **без коду взагалі**
  (найпевніше тому, що «ГП» уже зайняте Перцович і Пташник). Це
  **Ганна Пірановська**; код їм проставляє `vchyteli.mjs`.
- **`ОГ`** (фізкультура) — це **Орест Горбатий**. У журналі ліцею його немає,
  а без запису звідти немає й `id`, тож телефона й «мого розкладу» в нього не
  буде — але в розкладі й довіднику стоїть ім'я, а не код. Такі коди живуть
  в `UNDECODED`.

### Контакти вчителів

Телефони живуть окремо, у `src/data/contacts.ts`, і **в git їх немає**: сайт
лежить на GitHub Pages, і публікувати робочі номери можна лише з дозволу школи.

Файл створює той самий `import-teachers.mjs`. Застосунок підключає його через
`import.meta.glob` ([`src/lib/contacts.ts`](src/lib/contacts.ts)) — тобто збірка
без файла не ламається, просто в довіднику немає кнопки з номером. Перевірити
можна так:

```bash
npm run build && grep -ro "380[0-9]\{9\}" dist/assets/ | wc -l
```

Локально (файл є) буде 54, у збірці з чистого клону — 0. Коли школа дозволить,
достатньо прибрати `src/data/contacts.ts` із `.gitignore`.

| 4 | 10:55 — 11:35 | 10 | 16:30 — 17:10 |
| 5 | 11:55 — 12:35 | 11 | 17:20 — 18:00 |
| 6 | 12:45 — 13:25 | 12 | 18:05 — 18:45 |

Періоди 1–6 — перша зміна, 7–12 — друга. В інтерфейсі уроки нумеруються по
порядку дня («1 урок», «2 урок»), а не за наскрізним періодом.

## Завдання й нотатки

Нотатка живе під ключем `клас|рррр-мм-дд|період` у localStorage — прив'язана до
конкретної дати, а не до дня тижня: домашнє здають у певний день, а не
«щовівторка». У вчителя простір ключів свій (`вч{id}`), бо його уроки з різних
класів, а запис — про його власний урок.

Період `0` — це нотатка не до уроку, а до цілого дня: чергування, прибирання,
що взяти з собою. Уроків з таким номером не буває, тож ключ вільний, а сам
запис сам стає першим у своєму дні при сортуванні (`DAY_PERIOD`).

[`src/lib/notes.ts`](src/lib/notes.ts) віддає їх списком (`allNotes`), а
[`TasksSheet`](src/components/TasksSheet.tsx) дістає предмет із розкладу того
дня. Якщо розклад відтоді змінився і уроку вже немає — запис усе одно
показується, просто без назви предмета: викидати написане не можна.

Нічого з цього нікуди не їде: ані сервера, ані акаунтів.

## Оновлення застосунку

`sw.js` копіюється з `public/` як є, тому між випусками він не змінювався — а
браузер оновлює service worker лише тоді, коли сам файл інакший. Через це
встановлений PWA не помічав нових версій: відкрита сторінка так і лишалася на
тій, з якої стартувала.

Тепер `stampServiceWorker` у [`vite.config.ts`](vite.config.ts) проставляє в
`sw.js` відбиток збірки — sha256 від `index.html`, у якому імена зібраних файлів
із хешами. Відбиток інакший рівно тоді, коли застосунок справді змінився:

```bash
npm run build && grep "const BUILD" dist/sw.js
```

Клієнтський бік — [`src/lib/update.ts`](src/lib/update.ts): питає про оновлення,
коли застосунок повертається на екран, і раз на пів години. Коли новий service
worker перебирає керування, сторінка перечитується — але не з-під рук: якщо
відкрита шторка, чекаємо, поки застосунок згорнуть.

## Підручники

Каталог PDF-підручників відкривається з іконки книжок у шапці. Список живе в
[`src/data/books.ts`](src/data/books.ts) і ключується паралеллю — усі класи однієї
паралелі (напр. 9-А, 9-Б, 9-В) бачать один перелік. Наразі є 5–9 класи
(143 файли з «Інтелекту України»).

```ts
{
  subject: 'ум',                  // код із SUBJECTS, назва береться звідти
  books: [
    {
      title: 'Українська мова, 9 клас',
      note: 'Частини 1–2',
      authors: 'І. В. Гавриш, Н. В. Семихат…',
      url: 'books/9/ukr-mova-1.pdf',
    },
  ],
}
```

Книжка без `url` показується в списку з підписом «ще немає» — так видно, чого
бракує, і ніхто не тисне на порожнє посилання.

`title` у групі головніший за назву предмета: алгебра й геометрія стоять у
розкладі одним кодом «М», а підручники в них різні. `subject` при цьому
лишається — за ним група знаходиться, коли підручники підбирає не клас, а
вчитель.

**Підручники вчителя.** Якщо ввімкнено розклад учителя, та сама іконка книжок
показує не клас, а його предмети по паралелях: `teacherGrades` дістає з
розкладу пари «паралель → коди предметів», `booksForGrade` лишає з паралелі
тільки їх. Паралель, у якій для його предметів книжок ще немає (10–11), у
список не потрапляє.

У книжки з файлом дві дії: **Читати** — відкриває PDF на весь екран прямо в
застосунку, і кнопка збереження — кладе файл на пристрій (Cache Storage,
окремо від кешу застосунку). Збережена книжка після цього відкривається без
інтернету: читалка бере її з пам'яті, а не з мережі.

### Завантажити файли скриптом

Якщо файлів багато, зручніше не перетягувати їх у панель, а залити скриптом.
Доступи S3 беруться зі змінних середовища — у код нічого не потрапляє:

```bash
npm i -D @aws-sdk/client-s3
export R2_ACCESS_KEY_ID=...
export R2_SECRET_ACCESS_KEY=...
export R2_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
node scripts/upload-books.mjs "шлях/до/папки/9"
```

Ім'я папки стає префіксом у сховищі: `.../9/bio-1.pdf` → ключ `9/bio-1.pdf`.
Ключі в `books.ts` мають збігатися з іменами файлів.

### Куди класти файли

`url` буває двох видів:

**Поруч із застосунком.** Покладіть файл у `public/books/9/` і вкажіть
`url: 'books/9/ukr-mova-1.pdf'`. Найпростіше, але GitHub не бере файли більші
за 100 МБ, а весь сайт на Pages має вкладатися в 1 ГБ. Підходить, поки
підручників небагато.

**Зовнішнє сховище.** Будь-яке пряме посилання на PDF:
`url: 'https://books.example.com/9/ukr-mova-1.pdf'`. Для великих файлів це
правильніший шлях — наприклад, Cloudflare R2: створити бучок, увімкнути
публічний доступ, залити PDF-и й підставити адреси. Головне, щоб посилання
відкривало сам файл, а не сторінку перегляду.

Сторінки малюються через pdf.js на canvas, а не показуються в `<iframe>`:
iOS Safari у фреймі віддає лише першу сторінку без прокрутки, і так уже багато
років. Свій рендер поводиться однаково скрізь, малює лише видимі сторінки
(у памʼяті максимум шість, тож 300-сторінковий підручник не кладе телефон) і
нікуди не веде зі сторінки — у встановленому застосунку немає адресного рядка,
тож із відкритого PDF не було б як повернутися. Кнопка «зберегти» віддає файл
системі через «Поділитися», а не звичайним посиланням.

Сам pdf.js вантажиться окремим шматком і тільки тоді, коли відкриваєш книжку —
на швидкість розкладу він не впливає.

Service worker навмисно **не кешує** `.pdf` автоматично — інакше кілька
підручників забили б пам'ять телефона. Зберігає лише те, що користувач сам
обрав кнопкою.

Для файлу з чужого домену потрібні заголовки CORS — інакше браузер не дасть
прочитати вміст, і зберегти на пристрій не вийде (читати онлайн усе одно можна).
Файли з `public/` таких обмежень не мають.

## Меню їдальні

Що дають на сніданок і обід — [`src/data/menu.ts`](src/data/menu.ts): п'ять
днів, Пн…Пт, у кожному список страв із «виходом» (масою порції). Переписано
руками з примірного меню їдальні — там це таблиця у Word, імпортувати нічого.

Меню затверджують на період, тому поруч зі стравами лежать `MENU_FROM` і
`MENU_TO`. Коли переглядуваний день поза ними, аркуш так і каже — «свіжішого
в їдальні ще не давали», а не видає старі страви за сьогоднішні.

```ts
{
  breakfast: [{ out: '150', name: 'Рис з овочами' }],
  lunch: [{ out: '120/5', name: 'Макарони відварні з маслом' }],
}
```

`out` — рядком, бо це не завжди число: «120/5» це страва плюс масло, «1 шт» —
яйце. Грами дописуються самі (`portion`), штуки лишаються як є.
