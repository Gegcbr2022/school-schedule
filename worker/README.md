# Тривога — свій маленький сервер

Один Worker на Cloudflare, який раз на хвилину питає alerts.in.ua і
кладе результат у R2 звичайним файлом. Застосунок читає цей файл повз
Worker — тобто задарма й без жодного токена всередині.

Це та сама схема, що й у розкладу: **дані — це файл, а не сервіс**.

```
cron раз на хвилину
        │
        ▼
  api.alerts.in.ua ──► Worker ──► R2/alerts.json ──► телефони
     (по токену)                  (публічний файл)
```

## Уже піднято

| | |
|---|---|
| Worker | `dzvinka-alerts`, cron `* * * * *` |
| Бакет | `alerts`, публічний, CORS `GET` звідусіль |
| **Адреса файла** | `https://pub-58a1b7943a104948a240730aaa5eb54a.r2.dev/alerts.json` |
| Ручне оновлення | `https://dzvinka-alerts.minecrafthacker1990.workers.dev/refresh?key=…` |

Токени лежать секретами Worker'а (`ALERTS_TOKEN`, `REFRESH_KEY`) і в
репозиторії їх немає — і бути не має. Забули `REFRESH_KEY` — просто
поставте новий, `/refresh` усе одно потрібен хіба що для перевірки: cron
оновлює файл щохвилини сам.

## Що потрібно один раз

1. **Токен alerts.in.ua** — безплатний, за заявкою:
   <https://alerts.in.ua/api-request>. Ліміт — близько 10 запитів на
   хвилину на токен; нам вистачає одного.
2. **Бакет R2** з назвою `alerts`. У панелі Cloudflare: R2 → Create
   bucket. Далі в Settings бакета:
   - **Public access** — увімкнути (з'явиться адреса `…r2.dev`);
   - **CORS policy** — дозволити `GET` звідусіль, інакше застосунок під
     походженням `dzvinka://localhost` файл не прочитає:

     ```json
     [{ "AllowedOrigins": ["*"], "AllowedMethods": ["GET"], "AllowedHeaders": ["*"] }]
     ```

## Запустити

```bash
cd worker
npx wrangler secret put ALERTS_TOKEN
npx wrangler secret put REFRESH_KEY
npx wrangler deploy
```

Перевірити, що все живе, — оновити файл руками:

```bash
curl "https://dzvinka-alerts.<ваш-субдомен>.workers.dev/refresh?key=<REFRESH_KEY>"
```

Має відповісти приблизно так:

```json
{"v":1,"at":"2026-09-22T10:31:00.000Z","regions":{"13":{"level":2,"since":"2026-09-22T10:05:00Z"}}}
```

Порожній `regions` — це не помилка, а тиша по всій країні.

## Сказати застосунку адресу

Адреса файла передається збіркою — у застосунку вона не зашита:

```bash
VITE_ALERTS_URL=https://pub-….r2.dev/alerts.json npm run build
VITE_PACK_URL=bundle VITE_ALERTS_URL=https://pub-….r2.dev/alerts.json npm run build:ios
```

Без `VITE_ALERTS_URL` застосунок про тривогу навіть не заїкається:
вкладки немає, нічого не питається, жодного запиту в мережу. Це
навмисно — щоб зібрати «Дзвінку» для іншої школи чи іншої країни можна
було й без усього цього.

## Скільки це коштує

Нуль. Cron-Worker — 1440 запусків на добу (безплатно до 100 000), R2 —
один запис на хвилину й читання файла телефонами (Class B, безплатно до
10 млн на місяць). 500 телефонів, які питають раз на хвилину протягом
шкільного дня, — це близько 5 млн читань на місяць.

## Чого тут немає

- **Пушів.** Справжній push означав би зберігати токени пристроїв, тобто
  завести базу з даними людей. Замість цього телефон питає сам: коли
  застосунок відкритий — раз на хвилину, коли закритий — тоді, коли iOS
  дасть фоновий час (`ios/App/Alerts.swift`). Це підстраховка, а не
  сирена, і застосунок ніде не обіцяє іншого.
- **Історії тривог.** Її віддає alerts.in.ua, і якщо вона колись
  знадобиться, ходити по неї треба звідси ж, а не з телефона.
