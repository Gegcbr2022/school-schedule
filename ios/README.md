# Дзвінка для iOS

Рідна оболонка навколо того самого веб-застосунку, що й на сайті.

## Що це і чому саме так

Уся логіка — час, групи, кабінети, чергування тижнів — лишається там,
де вона вже написана й покрита тестами: у `src/`. Оболонка нічого з
цього не повторює. Вона робить те, чого веб сам не вміє:

1. **Віддає файли з пакета під сталим походженням.** Не `file://`, а
   власна схема `dzvinka://localhost` — інакше `localStorage` у WKWebView
   ненадійний, а в ньому всі профілі, нотатки й домашка
   ([`LocalAssets.swift`](App/LocalAssets.swift)).
2. **Відповідає на дотик.** Коротке «клац» під пальцем на перемиканні дня,
   групи чи профілю; окремий відгук на збереженні й на видаленні
   ([`Haptics.swift`](App/Haptics.swift),
   [`src/lib/haptics.ts`](../src/lib/haptics.ts)). Саме це найбільше й
   відрізняє застосунок від сайту.
3. **Прибирає панель «↑ ↓ Готово» над клавіатурою** — ту, що одразу видає
   веб усередині ([`KeyboardBar.swift`](App/KeyboardBar.swift)).
4. **Показує справжні діалоги.** Без цього `confirm()` у WKWebView мовчки
   повертає `false`, і кнопки «прибрати» не роблять нічого
   ([`WebHost.swift`](App/WebHost.swift)).
5. **Відкриває зовнішні посилання в Safari** — підручники з хмари,
   телефони вчителів.
6. **Каже вебу, що він усередині застосунку** (`window.__native`), щоб той
   не пропонував «додати на початковий екран» і не реєстрував service
   worker ([`src/lib/native.ts`](../src/lib/native.ts)).
7. **Ставить локальні сповіщення** — про початок уроку чи гуртка, кінець
   уроку і записану домашку. Веб рахує, що саме треба нагадати, оболонка
   лише просить дозвіл iOS і планує `UNCalendarNotificationTrigger`
   ([`Notifications.swift`](App/Notifications.swift),
   [`src/lib/notifications.ts`](../src/lib/notifications.ts)).
8. **Тримає екран запуску в колір теми**, щоб не блимало білим у темряві.

Ані CocoaPods, ані Capacitor, ані будь-якої іншої залежності тут немає —
і не треба. П'ять файлів Swift, разом менші за чотириста рядків.

### Як перевірити відгук на дотик

Симулятор Taptic Engine не має, тож на око нічого не видно. Зате місток
видно в логах:

```bash
xcrun simctl spawn booted log show --last 2m --info \
  --predicate 'subsystem == "app.dzvinka"'
```

Кожен дотик до перемикача має дати рядок `haptic selection`, збереження —
`haptic success`, видалення — `haptic warning`.

## Зібрати й запустити

```bash
npm run build:ios
open ios/Dzvinka.xcodeproj
```

`npm run build:ios` збирає веб у `ios/Web` — саме звідти Xcode бере його
в пакет. Якщо запустити збірку в Xcode без цього, вона зупиниться з
поясненням, а не з незрозумілою помилкою.

З командного рядка:

```bash
xcodebuild -project ios/Dzvinka.xcodeproj -scheme Dzvinka \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
```

## Розклад оновлюється без App Store

Це головне, заради чого все влаштовано саме так. Дані школи не зашиті в
застосунок намертво: у пакеті лежить «насіннєва» копія, а свіжу він сам
підтягує з мережі й запам'ятовує
([`src/lib/packUpdate.ts`](../src/lib/packUpdate.ts)).

Тобто перенесли урок у середу — замінили один JSON на сервері, і завтра
вранці всі бачать нове. Перевірка Apple тут ні до чого: вона потрібна
лише тоді, коли міняється сам застосунок.

За замовчуванням застосунок шукає розклад поруч із собою, а в пакеті
«поруч» — це той самий пакет, тож для збірки, яка ходить по дані на ваш
сервер, треба вказати адресу явно:

```bash
VITE_PACK_URL=https://gegcbr2022.github.io/school-schedule/data/school.json npm run build:ios
```

## Додати екран або функцію

Новий файл Swift просто кладеться в `App/` — і все. Тека підключена
«синхронізованою групою», тож Xcode бачить її вміст сам, а
`project.pbxproj` руками правити не треба й конфліктів у git на ньому не
буває.

## Чого тут свідомо немає

- **Віджетів і Live Activities.** Саме вони — найсильніше, що може дати
  рідний застосунок розкладу: урок і час до дзвінка просто на замку
  екрана. Це окреме розширення на SwiftUI, яке читатиме той самий пак.
  Наступний крок, коли застосунок поїде в App Store.
- **Обробки `back`.** У застосунку немає маршрутів: шторки — це стан, а не
  адреси. Жести «назад» вимкнено навмисно, щоб не виглядало як браузер.

## Перед відправкою в App Store

- `PRODUCT_BUNDLE_IDENTIFIER` = `app.dzvinka.schedule`, `MARKETING_VERSION`
  і `CURRENT_PROJECT_VERSION` — у налаштуваннях цілі.
- Команда розробника й підпис — `CODE_SIGN_STYLE = Automatic`, достатньо
  вибрати команду в Xcode.
- Іконку робить `npm run icons`: вона кладе `icon-1024.png` у
  `App/Assets.xcassets/AppIcon.appiconset`, решту розмірів Xcode зробить сам.
