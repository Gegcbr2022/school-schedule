# Дзвінка для iOS

Рідна оболонка навколо того самого веб-застосунку, що й на сайті.

## Що це і чому саме так

Уся логіка — час, групи, кабінети, чергування тижнів — лишається там,
де вона вже написана й покрита тестами: у `src/`. Оболонка нічого з
цього не повторює. Вона робить те, чого веб сам не вміє:

1. **Віддає файли з пакета під сталим походженням.** Не `file://`, а
   власна схема `dzvinka://localhost` — інакше `localStorage` у WKWebView
   ненадійний, а в ньому всі профілі, нотатки й домашка
   ([`LocalAssets.swift`](App/LocalAssets.swift)).
2. **Відповідає на дотик.** Коротке «клац» під пальцем на перемиканні дня,
   групи чи профілю; окремий відгук на збереженні й на видаленні
   ([`Haptics.swift`](App/Haptics.swift),
   [`src/lib/haptics.ts`](../src/lib/haptics.ts)). Саме це найбільше й
   відрізняє застосунок від сайту.
3. **Прибирає панель «↑ ↓ Готово» над клавіатурою** — ту, що одразу видає
   веб усередині ([`KeyboardBar.swift`](App/KeyboardBar.swift)).
4. **Показує справжні діалоги.** Без цього `confirm()` у WKWebView мовчки
   повертає `false`, і кнопки «прибрати» не роблять нічого
   ([`WebHost.swift`](App/WebHost.swift)).
5. **Відкриває зовнішні посилання в Safari** — підручники з хмари,
   телефони вчителів.
6. **Каже вебу, що він усередині застосунку** (`window.__native`), щоб той
   не пропонував «додати на початковий екран» і не реєстрував service
   worker ([`src/lib/native.ts`](../src/lib/native.ts)).
7. **Ставить локальні сповіщення** — про початок уроку чи гуртка, кінець
   уроку і записану домашку. Веб рахує, що саме треба нагадати, оболонка
   лише просить дозвіл iOS і планує `UNCalendarNotificationTrigger`
   ([`Notifications.swift`](App/Notifications.swift),
   [`src/lib/notifications.ts`](../src/lib/notifications.ts)).
8. **Тримає екран запуску в колір теми**, щоб не блимало білим у темряві.
9. **Передає розклад віджетам** через App Group. SwiftUI-розширення
   показує поточний урок, наступний урок і день розкладу
   ([`Widgets.swift`](App/Widgets.swift),
   [`DzvinkaWidget.swift`](Widget/DzvinkaWidget.swift)).
10. **Синхронізує Apple Watch** через Watch Connectivity. Годинник
    зберігає розклад активного профілю на сім календарних днів і
    самостійно рахує поточний урок за київським часом
    ([`WatchSync.swift`](App/WatchSync.swift), [`Watch`](Watch)).
11. **Тримає урок на екрані блокування** живою активністю
    ([`LiveActivity.swift`](App/LiveActivity.swift),
    [`DzvinkaLiveActivity.swift`](Widget/DzvinkaLiveActivity.swift)). Стан
    активності оголошений у теці [`Shared`](Shared), яка входить одразу в
    два таргети: розбіжність у полях між застосунком і розширенням
    `ActivityKit` карає мовчазною відмовою запускатись, без жодної помилки.
12. **Стежить за повітряною тривогою, коли застосунок закритий**
    ([`Alerts.swift`](App/Alerts.swift)). Поки він відкритий, стан питає
    веб; у фоні це може робити лише оболонка — присплений WKWebView
    мовчить. Вона ж рахує, на який урок повертатись після відбою: уроки
    вже лежать у знімку для віджетів, тож рахувати їх удруге не треба.
13. **Відповідає Сірі** ([`Intents.swift`](App/Intents.swift)): «який
    зараз урок», «що далі», «скільки до дзвінка» — з того самого знімка,
    без відкривання застосунку й без мережі.
14. **Просить оцінити застосунок** ([`Review.swift`](App/Review.swift)).
    Коли саме — вирішує веб ([`src/lib/review.ts`](../src/lib/review.ts)):
    не на запуску, а після п'ятого дня користування й тоді, коли уроки
    вже закінчились.

Ані CocoaPods, ані Capacitor, ані будь-якої іншої залежності тут немає —
і не треба.

### Про фон і чесність

`BGAppRefreshTask`, на якому тримається стеження за тривогою, — це
**прохання, а не таймер**. Коли його виконати, вирішує iOS, зважаючи на
батарею, мережу й те, як часто застосунок відкривають. Тому сповіщення
про тривогу — підстраховка, а не сирена, і ніде в застосунку не
обіцяється інше. Так само й жива активність: запустити її з фону, поки
застосунок жодного разу не відкривали, не можна без push-to-start
токенів, тобто без сервера.

Якщо колись знадобиться справжній push — це окремий сервер із токенами
пристроїв, тобто база з даними людей. Саме тому його тут і немає.

### Як перевірити відгук на дотик

Симулятор Taptic Engine не має, тож на око нічого не видно. Зате місток
видно в логах:

```bash
xcrun simctl spawn booted log show --last 2m --info \
  --predicate 'subsystem == "app.dzvinka"'
```

Кожен дотик до перемикача має дати рядок `haptic selection`, збереження —
`haptic success`, видалення — `haptic warning`.

## Зібрати й запустити

```bash
VITE_PACK_URL=bundle npm run build:ios
open ios/Dzvinka.xcodeproj
```

`npm run build:ios` збирає веб у `ios/Web` — саме звідти Xcode бере його
в пакет. Якщо запустити збірку в Xcode без цього, вона зупиниться з
поясненням, а не з незрозумілою помилкою.

З командного рядка:

```bash
xcodebuild -project ios/Dzvinka.xcodeproj -scheme Dzvinka \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
```

## Розклад оновлюється без App Store

Це головне, заради чого все влаштовано саме так. Дані школи не зашиті в
застосунок намертво: у пакеті лежить «насіннєва» копія, а свіжу він сам
підтягує з мережі й запам'ятовує
([`src/lib/packUpdate.ts`](../src/lib/packUpdate.ts)).

Тобто перенесли урок у середу — замінили один JSON на сервері, і завтра
вранці всі бачать нове. Перевірка Apple тут ні до чого: вона потрібна
лише тоді, коли міняється сам застосунок.

За замовчуванням застосунок шукає розклад поруч із собою, а в пакеті
«поруч» — це той самий пакет, тож для збірки, яка ходить по дані на ваш
сервер, треба вказати адресу явно:

```bash
VITE_PACK_URL=https://gegcbr2022.github.io/school-schedule/data/school.json npm run build:ios
```

## Додати екран або функцію

Новий файл Swift просто кладеться в `App/` — і все. Тека підключена
«синхронізованою групою», тож Xcode бачить її вміст сам, а
`project.pbxproj` руками правити не треба й конфліктів у git на ньому не
буває.

## Чого тут свідомо немає

- **Live Activities.** Наявні віджети використовують WidgetKit; це не
  Live Activity і не Dynamic Island.
- **Обробки `back`.** У застосунку немає маршрутів: шторки — це стан, а не
  адреси. Жести «назад» вимкнено навмисно, щоб не виглядало як браузер.

## Перевірка віджетів

Фон домашніх віджетів адаптується до системної світлої або темної теми.
Зворотний відлік використовує `Text(timerInterval:countsDown:showsHours:)`,
тому йому не потрібне щохвилинне відкриття застосунку. Коли система
повідомляє `isLuminanceReduced`, показується час наступної межі уроку за
Києвом. Це стабільний орієнтир для Always-On; частоту оновлення екрана й
перехід між записами timeline все одно визначає iOS.
Знімок містить сім днів; віджети вибирають актуальну київську дату.
Зміна секунд або хвилин не надсилає той самий розклад повторно на Watch.

Перед релізом на фізичному iPhone:

- Перевірити «Що зараз», «Наступний урок» і «День уроків» у світлій,
  темній та тонованій темах домашнього екрана.
- Перевірити круглий, прямокутний та однорядковий віджети екрана
  блокування під час уроку й перерви.
- Заблокувати iPhone з Always-On на кілька хвилин, перевірити час кінця
  уроку, потім розбудити екран: відлік має відповідати поточному часу.
- Перевірити межу початку/кінця уроку й відсутність відліку після
  останнього уроку. Симулятор не підтверджує поведінку фізичного Always-On.

## Apple Watch

`DzvinkaWatch` — окремий нативний застосунок SwiftUI для watchOS 10 і
новіших, вкладений у застосунок iPhone. На годиннику доступний швидкий
погляд на поточний урок із таймером і наступний урок. Нижче відкривається
окремий повний розклад із вибором одного із семи закешованих календарних
днів. Профіль обирається на iPhone. Домашка, PDF-підручники та редагування
налаштувань залишаються на телефоні.

Після першої синхронізації локальний кеш розкладу працює без з'єднання з iPhone.
Після закінчення збереженого тижня потрібно відкрити «Дзвінку» на
iPhone, щоб отримати наступні дні. Системний канал `updateApplicationContext`
передає найновіший знімок, коли може; кнопка оновлення на годиннику
додатково запитує збережений знімок, якщо телефон досяжний. У режимі
Always-On показується абсолютний час найближчої межі уроку за Києвом,
щоб орієнтир не залежав від замороженого відліку.

Перевірка моделі без симулятора watchOS:

```bash
swift test --package-path ios
```

Для запуску інтерфейсу оберіть схему `DzvinkaWatch` і спарений симулятор
Apple Watch. На фізичній парі перевірте початкову синхронізацію, зміну
профілю, роботу без телефона поруч, перехід на наступний день і
закінчення семиденного кешу. Для релізу потрібен provisioning нового
bundle ID `app.dzvinka.schedule.watchkitapp` у тій самій команді.
Для детермінованого перегляду повного дня в Debug-збірці watchOS Simulator
можна передати `SIMCTL_CHILD_DZVINKA_PREVIEW_DAY=YYYY-MM-DD` під час запуску;
ця змінна доступна лише симулятору й не входить до Release-збірки.

## Перед відправкою в App Store

- `PRODUCT_BUNDLE_IDENTIFIER` = `app.dzvinka.schedule`, `MARKETING_VERSION`
  і `CURRENT_PROJECT_VERSION` — у налаштуваннях цілі.
- Команда розробника й підпис — `CODE_SIGN_STYLE = Automatic`, достатньо
  вибрати команду в Xcode.
- Іконку робить `npm run icons`: вона кладе `icon-1024.png` у
  `App/Assets.xcassets/AppIcon.appiconset`, решту розмірів Xcode зробить сам.
